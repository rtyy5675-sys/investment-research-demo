# 见微 · 个人连续研究助手

把公司财报中的数据与用户关心的问题连起来：确认公司和报告期，读取实际财务数据，区分披露事实与推断，并说明仍缺少什么证据。研究记忆可以跨会话延续关注点和未解决的问题；用户可查看、修改、停用或删除。

## 为什么做

个人投资者看到财报或公告时，往往不只想知道一个数字是什么意思，还想知道它与自己一直关注的问题有什么关系、哪些判断依据变了、还缺什么资料。每次重新交代背景、翻旧报告、核对期间与口径，也让研究难以连续推进。

## 已确定的长期方向：个人投资研究 Agent

我的产品判断是，金融 Agent 的重要发展方向之一，是从回答单个问题，走向长期理解个人并持续服务其研究与决策过程。见微要成为越来越懂用户的 personal agent。它会在持续使用中理解用户正在研究什么、为什么关注，以及用户表达出来的疑惑、对风险的恐惧、对机会的贪婪与期待、过去如何权衡；用户不必每次从头解释，Agent 能沿着个人研究脉络接住新的疑问和资料。

这种理解要落在可见的帮助上：记得用户明确表达的关切与研究进度，把新披露和个人问题联系起来，说明哪些依据改变了、哪些疑问仍在，并让用户随时查看、更正或停止沿用。个人化依据来自用户表达和可核对的研究过程，逐步形成；疑惑、恐惧与贪婪由用户表达，Agent 不替用户揣测。Agent 协助理解和判断，最终取舍由用户作出。

## 24 小时 MVP 做到哪里

这次练习只有 24 小时，无法完整呈现一个长期个人 Agent。因此原型只做核心记忆的最小链路，让访客能看到主线：用户提出疑问 → Agent 接续明确的个人关注和未决问题 → 获取并解释新资料 → 用户可以纠正记忆 → 后续研究从这里继续。

首版用单家 A 股财报研究承载这条链路，并提供足够的取数、补查和可视化，让核心记忆能在实际任务中被看见。当前工程支持：

- 单家 A 股公司年报及一季度、上半年、前三季度累计数据，读取利润表、现金流量表和资产负债表中的已接入字段，并按可比期间分析。
- 通过扶摇 MCP 获取财务数据；可检索公告或上传文本型 PDF，对已支持的原始披露字段补查。
- 单一对话助手跨会话延续明确的研究关注与未解决问题；用户可以查看、修改、本次不用、停用或删除相关记忆。
- 用图表呈现财务变化，并允许查看数值和对应资料；回答区分披露事实、分析推断、资料缺口与下一步核查。
- 模型通过兼容 API 配置；工具失败、范围变化和资料不足应明确呈现，不能沿用旧范围结果冒充新证据。

这是一个单用户原型。记忆的基础机制和有限案例有测试或运行记录，但 Agent 是否能长期准确理解用户、减少重复解释、帮助用户更好地把握疑惑与取舍，仍需在连续使用中验证；当前演示的记忆范围和存储能力也不等于完整的个人 Agent。

## 后续版本：从核心记忆走向个人 Agent

产品方向已经确定，后续版本会沿着“逐步理解个人、持续推进个人研究”扩展。下面是发展路径，除当前首版明确列出的能力外，其余均为后续迭代，尚未在本原型完整实现：

| 后续阶段 | 发展方向 | 对个人 Agent 的作用 |
| --- | --- | --- |
| 个人上下文深化 | 逐步维护用户明确表达的疑问、关注、担忧、期待、研究假设和取舍变化 | 让新回答接住用户此刻真正想弄清的问题，并允许用户查看、更正、停用或删除相关记忆 |
| 连续研究推进 | 把个人关切与已解决事项、未决问题、新证据和后续核查连起来 | 用户回来时少重复交代，Agent 从上次停下的位置继续研究 |
| 主动跟踪个人关注 | 对用户选择跟踪的公司、假设或条件发现新披露时，解释与其关注的关系 | 让提醒由个人关注驱动，并提供来源、时间和可关闭的控制 |
| 更完整的投资信息背景 | 加入市场预期、估值、股价反应、多公司与行业比较，再逐步扩展到其他市场和资料类型 | 为“信息是否已计价”等疑问补充有时间戳、可追溯、口径一致的数据，并保持公司、期间和市场范围可核查 |
| 更丰富的 Agent 协作 | 在需要时让专业研究角色协同，用户仍可沿着个人 Agent 的主线沟通 | 只有证明能改善取证、解释或用户理解后再引入，避免角色数量代替实际价值 |

## 明确暂不做

- **本次因 24 小时限制而未完整呈现：**多对象研究、个人关注驱动的持续跟踪、市场预期与估值、股价反应分析、其他市场及资料类型、长期云端记忆。它们属于个人 Agent 的后续发展方向，不是方向待定，也不是当前已交付能力。
- **本次选择先做的核心：**个人记忆最小链路及其控制方式，并用一个具体财报任务展示 Agent 如何接住用户的问题、更新研究依据、让用户修正理解。
- **产品职责边界：**不对涨跌作确定性预测、不承诺收益、不替用户发出买卖指令。产品持续提供与个人问题相关、可追溯的研究依据，帮助用户自己判断。

方向与首版边界见[个人连续研究产品方向](docs/个人连续研究产品方向.md)；范围与验收细节见[通用研究产品](docs/通用研究产品.md)、[产品与评审入口](docs/评审入口.md)和[跨会话记忆验收](docs/跨会话记忆验收.md)。

## 本机运行

需要 Node.js 20.19 或更新版本。

```sh
npm ci
npm start
```

打开 `http://127.0.0.1:8791`。`npm start` 会构建 React 界面并启动本机服务。开发预览可在服务运行时另开终端执行 `npm run dev`。

在界面“模型 API”中配置服务地址、模型名和 API Key。数据服务凭证放在项目根目录 `.env.local`：

```env
FUYAO_API_KEY=your-key
```

`.env.local` 已被 Git 忽略。模型 Key 保存在本机 `artifacts/model-settings.json`，不会返回浏览器。连接验证只检查基础结构化输出和 MCP 工具发现；完整研究仍需按实际任务检查。
