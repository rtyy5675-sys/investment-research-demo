# 公告与财报补查闭环

日期：2026-10-15。状态：本机已实现，并完成两家公司真实年报取证、模型分析及异常保护验收；不代表所有财报格式均已验证。

## 交付内容

同一条研究链路支持：恢复上次未决问题 → 按公司代码和报告期检索巨潮资讯原始财报，或上传文本型 PDF → 提取合并现金流分项 → 程序核验 → 更新判断和研究进度。

这条通用能力当前聚焦五个字段：经营活动现金流入小计、流出小计、销售商品及提供劳务收款、购买商品及接受劳务付款、经营现金流净额。公司、数值和判断均来自当前任务及资料，没有茅台专用分支。它尚不是任意附注、任意问题的通用文档问答。

结果明确显示本轮新增与沿用的资料、实际取证次数、收支变化表、原文页码，以及这次解决了什么、仍不能判断什么。用户可从“补充原始财报”选择检索或上传。

## 如何避免“找到一份 PDF 就开始下结论”

1. 公告搜索按公司代码动态取得 orgId，筛选目标报告期和完整报告，不使用公司映射表；下载只允许巨潮静态 PDF 域名并校验重定向。
2. PDF 原文只作资料。按页抽取文字，选择公司身份页及现金流量表附近内容；无可用文本时停止，不声称已完成 OCR。
3. 模型给出字段、原文引文、页码和列位置。程序逐项核验原文存在、公司名称及代码、合并而非母公司口径、期间和单位，并以精确十进制核对本期与上期“流入减流出等于净额”。
4. 校验通过才加入证据；新的回答必须实际引用新证据。不同来源净额若冲突，分别展示，不拼接新旧来源计算。
5. 每次补查有独立 revision。过期上传返回 409；错误公司、期间或表格不能覆盖有效结果；补查失败明确呈现阻塞，并可再次检索或换文件。

原始文件按 SHA-256 去重保存在本机；页级文本独立存储，不把整份年报反复塞进上下文。Trace 保存下载、提取、校验、失败和本轮证据来源；界面默认展示用户需要核对的引文，不直接铺开模型用 JSON。

## 真实失败与修正

首次真实提取时，模型将单位扩写为完整短语，并把报表年度列改写成日期描述，严格原文校验拒绝了结果。修正为明确的单位枚举和原样保留期间、引文的要求，并允许在剩余预算足够时进行一次定向修复。未放宽公司、引文、列位或算术校验。原失败仍在本机 Trace 中。

另修正了复用已核验 PDF 后没有刷新本轮补查状态的问题，防止历史失败标记留在成功结果上。

## 当前边界

公告检索覆盖沪深公司；北交所可尝试上传，但尚未验证其报告格式。搜索元数据已检查年报、半年报和季度入口，完整取证与回答本轮只验收了两家公司 2025 年报。文本 PDF 最大 16 MB、600 页；扫描件、加密文件、未覆盖的特殊表格不自动降级为猜测。银行等报表缺少必需字段时应明确失败。市场预期、股价定价程度、任意财报附注及 OCR 不在本次交付范围。

## 代码入口与复现

- `lib/disclosure-search.mjs`：公开公告搜索及报告筛选。
- `lib/report-pdf.mjs`：页级解析、提取合同、独立校验。
- `lib/disclosures.mjs`：文件存储、预算内取证、缓存、证据及收支拆分。
- `lib/general-research.mjs`：与原任务、补查、判断更新接合。
- `src/DisclosurePanel.jsx`：检索和上传入口；`src/ResearchDecision.jsx`：判断更新表。
- `scripts/verify-disclosures.mjs`：需要本机服务、可用模型与扶摇 Key；会产生实际模型调用。验收基线主动关闭自动取证，仅用于观测补查前后差异；正常产品默认会在发现对应缺口时尝试取证。

运行 `node scripts/verify-disclosures.mjs` 可建立新的两家公司验收任务。原始任务及模型记录位于被 Git 忽略的 `artifacts`，不应将其中可能含用户输入的资料直接公开。
