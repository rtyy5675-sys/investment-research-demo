# 跨会话研究延续修复

> 后续收尾补丁已修改源码，按用户要求暂未测试、构建或打包。下文147项测试及真实演示属于补丁之前的版本，不代表新补丁已验证。新变更见[记忆意图与界面收尾](记忆意图与界面收尾_2026-10-15.md)。

## 结果与边界

沿用现有个人研究 store、版本屏障和对话界面。本轮接通“有效结果发布后写进度 → 新会话按同一服务端个人身份与公司读取 → 影响取证与回答 → 成功提交更新”。没有另建记忆服务。

当前是本机个人空间，不是已经上线的多账号系统。服务端 `RESEARCH_OWNER_ID` 可隔离测试身份；默认 `local-personal`。客户端不能指定 owner。预览 Basic Auth 不等于用户登录。

## 实际修改

- 原先记忆在规划后才加载：现在在规划前尝试唯一精确公司/代码匹配，再由标的查询确认公司，重新检查有效版本。当前明确要求优先；“这次怎么样”不当作拒绝历史。新会话不继承旧年份；最新期间仍须实际查询确认。
- 同一记录新增 `open_questions`、`resolved_questions`、`evidence_refs`、`current_result`。旧字段由它们兼容投影。未决状态按 `progress.remainingQuestion` 更新，不从过期条件卡恢复问题。
- 已核验的五项现金流数据与程序 `cashBridge` 只关闭“流入流出的算术贡献”问题，不宣称回款质量、完整构成或原因均已解决。其他旧问题需要明确的 `resolvedQuestionIds`，并由程序和独立回答核验共同检查。
- 证据引用定位到源会话及已发布版本，核对 owner、公司、scopeKey；从真实保存的证据和 PDF 重新读取。旧记录仅有 source 指针时，可从该版本恢复原来漏存的 PDF。新期间不复用旧年金额。
- 同期资料已经齐全时允许不再查询汇总表。附注读取从已核验报告中选择相关逐字窗口，保留 PDF 页码；不混用母公司现金流表。此次新资料来自附注原文，不是把旧分析改写成“证据”。附注检索为关键词及页面窗口，尚不保证覆盖全部项目、原因或所有公司报告格式。
- “本轮不看”不覆盖长期关注；“以后改为”通过同一 CAS 更新默认并使旧运行失效；归属纠正保存原话和来源。研究疑问不会因“那是别人观点”就被错误改为他人立场。
- 保留停用不读不写、删除防旧任务复活、晚返回版本不能回写、先存结果再写个人记录。只有本任务本版本确实提交成功，前端才显示个人研究记录已更新。
- 前端沿用原布局：主回答附近展示实际读取进度；右栏分进入时未决、本轮更新；来源与控制保留。运行记录提供 planning_read、context_used、evidence_restored、correction、commit，含版本与来源；不是仅列 used_context_ids。

## 一条真实路径

验收使用隔离目录及构造的演示关注，不代表用户真实持仓或投资偏好。起点来自已经实际完成的贵州茅台2025年财报补查与其原始 PDF；验收中人工建立了这一初始关注，未将此设置包装成用户自然使用证据。

新会话只问：

> 贵州茅台2025年年报，这份资料对我之前的问题有什么帮助？

没有重述现金流关注或下一步项目。规划阶段已读到同公司记录；本轮沿用2项证据、新读1项附注，汇总财务报表查询0次，原文读取1次。模型、证券识别与原始财报均为真实链路；财务表复用此前的真实查询，不称为本轮新查询。

本轮实际推进：原来已完成的收支算术贡献未再列为缺口。新取得的年报原文解释了部分变化涉及财务子公司的集团成员存款、同业资金存放等项目，其他经营现金收入增加涉及到期存款利息。回答仍明确：这不是完整归因，也不足以判断销售客户回款质量。

更新后自动提交成功。重启服务重新读取同一任务及记录，进度、PDF引用、页码与版本仍存在。详细任务、输出和运行编号见 真实验收记录（原始记录本地保留；参见[公开测试摘要](evidence/public-test-summary.json)）。

## 复现

- `npm test`
- `npm run verify:memory`（合成模型及合成公司，只测运行机制）
- `node scripts/verify-continuity-real.mjs`（需要现有真实模型配置、扶摇Key及先前公开财报验收文件；会创建隔离个人空间并产生真实模型调用）

可从已有正常会话完成研究，点击“新的研究”，输入同一公司的名称/代码与当前期间，再问“这对之前的问题有什么帮助”。是否需要澄清以实际公司和期间信息是否唯一为准。
