# M09：停用期间不召回、不自动写入

日期：2026-10-15。状态：本机专项回归通过；不是整套交接验收通过。

## 问题与修改

原`capture`只检查任务自己的记忆开关，没有拒绝已有的`entry.disabled=true`。新会话虽未召回，结束时仍会重写已停用条目的研究进度、来源和版本。旧测试甚至接受这次写入，现已改为拒绝。

- 存储层先检查对象停用状态，拒绝自动捕获，不改记忆内容、版本或捕获记录；重复保存同样不能写入停用条目。
- 确认公司后、生成回答前，仅记录该对象的记忆ID、版本与开关。提交时再比对这份`captureFence`，防止“运行中停用又启用”或“停用期间开始、启用后返回”造成迟到回写。
- 停用期间的任务仍可完成普通财务研究，记忆保存状态为`skipped`。重新启用只改变开关和管理版本，不补写关闭期研究；之后新发起的研究可正常保存。
- 记忆策略读取失败时，该轮也不自动捕获，避免绕过未知开关。

“不召回”指研究记忆不进入模型输入。管理界面和执行器仍需读取本机开关状态；研究聊天、任务和Trace照常保存，不等同于删除会话。
