本机服务：[打开产品](http://127.0.0.1:8791/)。当前为可操作的React界面，实际安装liquid-gooey 0.2.2。未部署到远程环境。

## 建议用这五步验收

1. 点击“查看已完成实例”，立即读取已保存的真实模型运行。它明确标为历史运行，不播放假进度。也可点案例卡片、发送问题，实际重新执行取证、核验和回答。
2. 读首次结果：能否看懂“营收下降不能直接说明卖不动”“利润增长仍不足以排除风险”，以及相应证据与缺口？点“3项依据”核对期间、单位和原始报告。
3. 切换研究Bot、核验Bot，查看实际任务分派、资料返回和核验交流；输入框会向所选Bot提问。核心任务不要求读完这些记录。
4. 新任务首次完成后点“继续补查关键证据”。补查取得产量、库存、分业务口径，结果应把研究推进到库存消化和收入解释的缺口，而不是直接判断滞销或买卖。
5. 通过更多操作修改问题或“模拟补查失败”。失败明确标注为故障注入，上一版有效结果保留。输入区“+”展开真正的Gooey快捷按钮。

## 当前边界与取舍

默认分步研究；多角色提示对照仍可选，但有限对照没有证明更好的质量，不增加独立Agent服务。只支持原测试公司2024全年公开资料包；它是基于真实披露设计的目标用户场景，不冒充用户访谈原话。市场预期是否计价、估值和其他公司的问题尚不支持。实时查询、跨浏览器兼容、真实用户价值和收益均未证明。

使用本机已登录模型执行新研究，耗时受模型服务影响。界面把已保存输出中的内部字段名availableFollowups翻译为“可补查资料列表”，不更改金融内容，原始记录完整保留。未来输出提示已补充不暴露内部字段名的规则，该提示措辞尚未再次运行完整模型链。

参考检索：[GitHub、Product Hunt与组件取舍](MVP参考与取舍.md)。当前采用assistant-ui的对话组织思路、Agent Chat UI的按需资料呈现思路；未迁移其完整运行框架。
