日期：2026-10-15。状态：部分执行。机制单元测试及4组隔离HTTP检查已运行；一次真实服务演示机制通过、回答效果未通过。固定9条序列尚未逐条完整执行，真实用户价值待观察。对应 [产品方向](个人连续研究产品方向.md)、运行证据（原始记录本地保留；参见[公开测试摘要](evidence/public-test-summary.json)） 与 [固定序列](../evaluation/memory-sequences.json)。

## 证据与状态

每条序列从独立用户或清洁记忆空间开始；序列内创建真正的新任务，不把原聊天完整粘贴到新任务冒充召回。公司、期间、资料快照及模型配置应可追溯。合成输入标为功能验收，不能称为真实用户投资需求观察。

每一步保留 taskId、消息、操作、有效记忆版本、召回与排除记录 ID、实际模型输入的相关片段、工具调用和最终回答。检查完成不等于通过：结果使用 pending / pass / fail / blocked，并写明证据位置和失败原因；未运行保持 pending。

分开判定三个层次：

1. **机制**：存储、隔离、范围匹配、纠正、排除、删除和重启行为。
2. **回答效果**：记忆是否改变了相关取证和解释，是否减少重复澄清；事实和立场是否保持准确归属。
3. **用户价值**：真实用户是否更少重复组织背景、能理解新证据如何影响原问题。只有真实观察可以给这一层通过。

## 内部对照

同一固定序列分别运行记忆开启与关闭版本。保持分析模型及配置、可用工具、资料快照、前置对话、后续输入、调用上限和评审判据一致；两边都经历相同前置会话，关闭版本不主动补发历史。另可增加“人工完整提供相关背景”的分析上限对照，但不能把它与无记忆条件混为一组。

分别记录用户需要重新说明的项目、错误召回、重复查询、命中主要未决问题、事实/归属错误、调用数与总耗时。所有记忆写入和检索成本计入，冷启动与后续使用分开报告。相同条件若也能靠现有任务状态解决，应如实说明，不归因成长期记忆优势。

不只比较个性化措辞。必须指出一条可观察的工作变化，例如“未再次要求解释关注点，直接针对上次现金流缺口取得新资料”。一组模拟结果不能证明稳定可靠、长期留存或理解提升。

## Claude 外部对照计划

先核实实际可用模型、金融工作流、记忆功能与工具权限，保存版本和配置。双方得到同样的前期对话、时间顺序、资料和后续任务；各自通过正常支持方式建立记忆。记录无法对齐的工具、数据与预算，必要时仅比较共同支持部分。

评审使用相同任务标准；尽可能隐藏输出来源、交错测试顺序并保留原始失败。没有实际运行 Claude 时仅保留计划，不写“已对标”“达到同等效果”或胜率。

## 真实用户观察

邀请确有复访研究行为的人，用自己的对象完成第一次任务，之后在新会话带来相关信息，再允许转向或纠正。小样本用于发现问题；不据此推断留存或商业规模。若用压缩时间的模拟第二次任务，须说明并非自然复访。

观察而非强制填写投资观点：用户是否重复交代、是否发现错误关联、能否说清新增资料的意义、哪些原条件仍未解决、什么会让自己重新检查。记录原话和操作，不把“它很懂我”自动当成判断质量提升。

## 发布前最小门槛

固定序列中的身份范围、当前指令优先、纠正、删除、财务时效及观点归属属于必过项。召回相关但没有帮助取证或解释的结果，只能判机制通过、价值未通过。关键取证能力仍受现有数据工具限制，不因接入记忆就视作补查闭环已经完成。
