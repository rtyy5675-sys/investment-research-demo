# 个人连续研究：产品方向与首版边界

日期：2026-10-15。

状态：方向、首版实现与有限验收。第9、10节保留v3.3首版及其失败记录；当前v3.5架构、三阶段续接、草稿后核验与新证据见[上下文手册审查与优化](上下文知识手册审查与优化_2026-10-15.md)。这些记录不证明长期用户价值已通过。用户粘贴对话中的 Claude、AlphaSense 功能及许可证说法未在本轮核实，本文不将其作为已核实竞品事实。

## 1. 定位与价值假设

面向会反复研究相同公司或相关问题的个人投资者，持续保存并维护个人研究上下文：为什么关注、研究到哪里、还缺什么、何时需要重新检查。用户新开会话后，可以继续推进问题，减少重新解释和比较旧答案的工作。

金融分析继续要求可追溯的事实、清楚的解释与可检查的边界。记忆主要改变问题选择和信息组织，不改变证据真假，也不替代本轮取证。

产品假设是：**相关背景能准确恢复并被纠正时，连续研究的重复工作会减少。**这不是已经验证的留存、付费、理解提升或投资效果结论。首次分析质量仍须独立成立。

## 2. 谁更可能需要

| 条件 | 具体表现 | 验证方式 |
| --- | --- | --- |
| 有复访对象 | 多次关注同一家公司，或同一投资逻辑下的有限对象 | 观察最近真实研究记录，确认重复任务实际发生 |
| 有连续问题 | 新公告出现后，会回看上次没解决的条件 | 让用户演示目前怎样找回旧资料与问题 |
| 有重新交代成本 | 需要重复描述关注点、翻旧结论、提醒工具继续查什么 | 记录旧流程中的操作、时间、遗漏及最终是否解决 |
| 愿意纠正上下文 | 能发现并修改“这是转述”“这次换关注点”等错误 | 观察纠正是否自然、后续是否生效；不强迫用户填写画像 |

偶尔问互不相关问题的人，不是首版价值验证的主要对象。不能因为会话数量多，就认定长期记忆有价值。

## 3. 记忆对象与归属

首版围绕“一个人，在一个研究对象上，为推进一个问题积累的上下文”组织。账户默认单一明确用户；若未来多人使用，必须先建立用户隔离，不能靠同一浏览器会话猜测身份。

| 类型 | 可保存内容 | 使用规则 |
| --- | --- | --- |
| 明确关注 | 用户明确说关注扩张是否依赖外部融资 | 默认限定该公司与研究主题，不升级为全局投资偏好 |
| 研究进度 | 已取得哪些资料、未决问题、上次停止原因 | 标明是研究状态，附任务及证据定位；不冒充用户判断 |
| 用户看法 | 用户明确表达并确认的原话、前提、条件 | 与 AI 分析分开；没表达立场就保持空，不自动看好或看空 |
| 用户纠正 | “这是转述，不是我的观点”“这次研究竞争格局” | 新纠正覆盖当前适用解释，保留来源与版本，不继续召回已纠正的错误理解 |
| 表达偏好 | 用户明确说先解释机制再列指标 | 在合适范围沿用，当前指令随时覆盖；不推断知识水平或风险承受力 |
| 暂定理解 | AI 从上下文提炼的研究目标 | 必须标为 AI 理解，可修改；不能作为用户已确认观点 |

不自动记录持仓、财富、风险偏好、交易意向或人格标签。询问一家公司不代表持有、看好、准备买入，也不代表希望得到支持性结论。

旧财务资料可以保留来源索引，但长期记忆中的摘要不成为最新财务事实。历史数字若参与新回答，仍要核对公司、期间、口径、抓取时间及必要的新数据。

## 4. 最小记忆合同

每条可被召回的记录至少能说明：

- **谁说的、从哪里来**：用户原话、AI 暂定理解或研究状态；关联会话、消息、任务版本及时间。
- **适用哪里**：用户、公司、主题和必要的报告期间。明确全局表达偏好须单独标记。
- **当前是否有效**：有效、已被纠正或删除；能定位后续修改，不能新旧两条同时当成当前要求。
- **本次为何使用**：当前问题与记录的相关性、被采用的记录 ID，以及当前指令是否覆盖它。

召回与写入应分开。用户对一段被召回文字的追问或转述，不能自动成为新的已确认立场。AI 分析中的推论也不能通过多次摘要变成用户事实。

## 5. 用户控制与呈现

保持一个主 Bot。相关时轻量显示“本次沿用你此前对现金回收的关注”，提供来源、修改、本次不用和删除入口；不要求用户先管理记忆才能研究。

| 操作 | 预期行为 |
| --- | --- |
| 修改 | 立即更新有效解释；后续新会话不继续沿用被纠正版本 |
| 本次不用 | 本轮规划、取证与回答排除该记忆；不等于删除，后续会话仍可在相关时使用 |
| 删除 | 从后续召回和模型输入中排除该记录；搜索索引或缓存同样失效 |
| 当前指令不同 | 当前明确要求优先；历史背景不限制用户转向 |
| 没有合适记忆 | 正常完成首日分析，不编造熟悉感，不为建立画像连续反问 |

删除记忆与删除原始聊天记录是不同操作，界面必须说明实际范围。没有实现和验证物理删除、备份清除时，不得宣称所有副本都已清除。删除后的失败重试、缓存及服务重启也不能复活可召回记录。

前台展示相关背景和取舍依据即可；无需向用户暴露全部内部编排。运行记录应保留召回记录 ID、范围、来源、使用/排除原因及版本，便于核查，不记录隐藏思考。

## 6. 主演示：一个对象、两次新会话、一次纠正

本演示可以使用合成上下文验证机制；公司财务结论必须来自实际资料，不能用编造数字冒充真实披露。

1. **会话 A**：用户明确关注甲公司扩张能否由经营现金支撑。产品解释已取得资料，保存当前关注和未决条件；用户不必选择投资立场。
2. **会话 B**：在不复制 A 聊天内容的新任务里，用户问“甲公司新报告出来了，这次怎么样？”产品恢复相关关切，核对新资料，解释它对上次未决条件的影响；不只增加一句个性化开场白。
3. **同一会话 B 纠正**：用户说“这个问题我已经理解了，这次只研究竞争格局”。产品按新关注继续，旧现金流问题不再支配默认取证或结论。之后再开会话，应使用纠正后的适用范围；固定验收另有第三会话检查。

展示时必须看得到：记忆来源、实际注入范围、取证/分析发生的变化、新旧财务资料的区分，以及用户纠正后的行为。若取不到关键新资料，应保留局部回答并说明缺口，不因有记忆就提高结论确定性。

## 7. 评测与完成标准

固定序列见 [memory-sequences.json](../evaluation/memory-sequences.json)，执行与人工观察规则见 [跨会话记忆验收](跨会话记忆验收.md)。文件是验收任务，不是已通过的结果。

首版机制通过至少要求：相关新会话能接续；不同公司不误用；新期间不沿用旧数字当现状；纠正生效；本次不用有效；删除后不再召回；未表达立场不生成观点。每条必须保存新会话 ID、注入记录与最终输出，不能只检查数据库存在条目。

“越用越好”仍需真实用户连续任务观察：重新解释是否减少、问题是否更快命中、误归属是否减少、用户是否理解新证据改变了什么。模拟跨会话只验证机制。

## 8. 对标与复用边界

成熟金融工作流可作为分析基线。首版不承诺达到 Claude 同等效果，不以像素级克隆、品牌呈现或增加记忆条数作为产品成功指标。复用具体开源实现时，再针对实际版本核查许可证与声明要求。

先做同模型、同工具、同资料的有无记忆内部对照，确认差异是否来自上下文延续。后续若有可用的 Claude 金融环境，再给双方相同的历史、资料、工具权限及后续任务做外部对照；未实际配置和运行的能力标为未测，不能用不对等历史制造优势。

## 9. v3.3首版实现边界（历史记录）

- `lib/personal-research-memory.mjs`：本机个人空间持久化，每公司一条活动研究记录，区分用户明确关注与 AI 暂拟理解，保存问题级进度、未决条件和来源，不保存整份金融回答或用户立场。
- 新会话首页可接着研究；记忆管理支持修改、停用/启用和删除；结果上方说明本次沿用了什么，并允许“本次不用”后对当前问题重新分析。
- 先确认公司再召回记忆；同对象记忆可以参与一次受预算约束的取证规划，然后重新取数。不能用旧研究年份代替本次期间。记忆命中时最多四次模型调用，比无记忆三阶段多一次规划，尚未证明收益覆盖这项成本。
- 修改使用版本比较；运行中更正或删除会取消使用旧记忆的任务。旧版本结果不能覆盖新编辑，删除后原任务不能重复捕获复活；原聊天保留，删除记忆不是删除历史会话。
- 自动保存的是 AI 提炼的研究问题与未决进度；用户可在“本轮关注”或记忆管理中明确、更正关注。尚未实现对所有自然语言转述、否定、立场或表达偏好的自动提取与更新，不能声称已经完全理解用户。
- 本机测试62项通过。4组隔离HTTP检查覆盖跨新会话接续、旧期间隔离、修改停启删除及本次不用；模型和MCP为合成返回，只证明协调机制。记录在 `artifacts/memory-verification/http-checks.json`。
- 原运行保障的7条隔离HTTP检查仍通过。真实服务与浏览器的连续会话记录见下一节。
- 一公司只有一条当前研究上下文，原会话保留历史；还没有多条投资假设账本、语义偏好检索、跨设备同步、账户鉴权或长期监控。
- 仍未接入公告/PDF原文和最终答案语义核验关卡；长期记忆不补足这些分析与资料缺口。
- Claude 外部对照：未开展。
- 真实用户连续任务、长期留存与付费验证：未开展。

后续补证时保留“设计、已实现、已运行、用户效果”四个状态，不能因文档或结构检查通过而升级结论。

## 10. 真实服务演示及失败记录

本轮使用真实 Codex 模型和扶摇 MCP，关注点由开发者构造，并在界面明确标注“演示关注，不代表你的真实偏好”；不是投资者访谈或真实复访观察。任务 A `2867bb1d-0907-4422-89ca-d45e54b27aee` 研究贵州茅台2024与2023年年报，随后在记忆管理中修改关注点。任务 B `219a428b-71d8-44bb-a924-a326103a0817` 是独立新会话，只问最新年报及接续未决问题，没有重新粘贴旧聊天。

**续接机制通过这一次演示**：B 实际采用 A 的记忆版本2，识别为600519.SH，重新查询2025与2024年现金流资料。确认公司前的规划不注入记忆，后续取证规划、口径检查与回答收到匹配记录；没有生成用户立场。浏览器中可看到来源期间2024年与本次研究2025年分开呈现。390与1280像素宽度没有页面横向溢出。

**回答效果未通过**：B 接上了经营现金流收支明细的旧缺口，但只查了现金流表；分析标题仍问“现金流是否支持利润增长”，却没有查利润。其“与主张相反”标签实际针对较窄的隐藏陈述“现金流净额增长”，与用户可见问题不完全对应，容易误读。净额下降本身也不能回答利润与现金的关系。这条失败保留，不能把任务 complete 当成效果通过。

优先修正方向是：相关比较所需的证据要完整；用户可见问题、待核主张、支持关系必须对应；取得原始披露补上工具缺失字段。暂缓扩大画像、更多记忆类型或增加 Bot。现有记忆功能不替代这些基础能力。

A 使用3次、B使用4次模型调用；问题、期间和证据不相同，不构成有无记忆的公平效果对照。尚未验证减少用户工作量、长期留存或 Claude 同等效果。

结构化证据见 memory-checks.json（原始记录本地保留；参见[公开测试摘要](evidence/public-test-summary.json)）。截图见 [记忆管理](../artifacts/memory-verification/memory-manager.png) 与 [跨会话续接](../artifacts/memory-verification/memory-continuation.png)。完整本机 Trace 按 taskId/runId 保存在 artifacts 中，证据摘要不复制原始财报数据。
