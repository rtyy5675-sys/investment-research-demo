## 结论与问题定位

原提示有回应问题、引用证据和防止越界的要求，但目标与细节的优先级不清楚。它要求 `judgmentChanges` 至少一项，核验又列出几乎全部报表注意事项，造成不必要的报告结构、重复解释和无关数字。并非完全没有设定预期，而是更容易优化“填完栏目”，没有同样明确“推进哪一个判断”。

“从第一性原理呈现”在本产品里的含义：解释用户正在判断的命题、它成立所需的经济关系和比较基准，再用证据说明哪些前提成立、哪些尚未验证。只输出可核对的理由，不索取或展示内部思考过程。也不能用一句“请从第一性原理思考”代替成功标准。

## 当前分层

| 层 | 职责 | 实际位置 |

| 程序约束 | 工具白名单、公司与期间匹配、引用 ID、任务版本归属、JSON 结构 | 模型适配、财务查询及状态模块 |

调用也作了分层：Codex CLI 使用本次进程的 `developer_instructions` 传入业务原则和阶段要求，任务资料通过 stdin 输入；兼容 API 分支使用 system 消息与 user 消息分开传递。没有修改全局 Codex 配置，也没有宣称替换了 CLI 平台自身的全部系统指令。新 Trace 保存指令、输入、Schema、版本、哈希及指令放置方式，旧记录保留。

本轮实际运行验证的是 Codex CLI 分支；兼容 API 分支仅修改与检查代码，未调用远程兼容接口验证。

必要的查询细节没有为了“抽象”而删除：如“上半年=累计二季度”“澄清回复继承待确认期间”，它们会实际影响取数正确性。

## 最新官方依据

- OpenAI Docs [Using GPT-6](https://developers.openai.com/api/docs/guides/latest-model#prompting-best-practices)：减少重复指令；分组修改，在同一任务上比较；保留表达产品要求或修复已观察问题的指导。指南里的内部评测数字不用于推断本产品提升。
- [Prompt engineering](https://developers.openai.com/api/docs/guides/prompt-engineering)：区分业务指令与动态输入，明确内容边界，以代码管理提示。
- [Reasoning best practices](https://developers.openai.com/api/docs/guides/reasoning-best-practices)：直接、明确地写目标和限制，不依赖“逐步展示思考”。这篇包含较早模型的建议，使用时以当前模型上的实际表现为准。
- [Codex configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference)：确认 `developer_instructions` 是附加开发者指令的配置项。

使用当前应用原有 `gpt-6-luna / low`，没有因查到其他型号的指南而更换模型。

## 发现并保留的问题

1. 初版 v2 重放把经营净现金流增长扩大成了“现金回收没有转弱”。v2.1 补充指标边界，再跑原题后不再出现这一表述。初版输出保留在 `artifacts/prompt-review/`，没有删掉失败记录。
2. v2.1 的比亚迪重放仍漏写“当前工具未接入”这句能力提示，虽然没有声称已执行外部查询。它还沿用了旧核验对“最新年报”的过度保守意见。说明指令不是硬保证，且上游核验质量会影响解读；不能记为所有标准通过。
3. 主界面的快速补查入口仍按剩余报表生成，不等于该报表最有助于当前判断。新版文字可以允许结束，但工具按钮的相关性需要另行处理。
4. 核验阶段发生在解读之前，属于证据与边界检查，不是最终答案的独立审查。引用 ID 合法也不能保证计算、因果解释或信息选择正确。

验收应继续看：是否答到了核心问题、理由是否支持结论、是否遗漏关键未知、下一步是否真能推进判断。少犯错、少输出字数和完整 JSON 均不能单独代表成功。
