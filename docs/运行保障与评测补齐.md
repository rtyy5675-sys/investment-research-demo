# 运行保障与评测补齐

日期：2026-10-15。当前运行时：`bounded-research-v1`。沿用 Prompt `research-decision-v3.2`，没有把三阶段研究改成自由循环。

## 本轮交付

| 项目 | 实现 | 验收边界 |
| --- | --- | --- |
| 主动停止 | 输入框旁“停止”；`POST /api/tasks/:id/stop` 绑定 expectedRevision；取消传到模型和 MCP；CLI 必要时 SIGKILL；保存 cancelled 与 user_cancelled | 停止不删除旧答案和成功检查点；不能撤销供应商已经发生的只读请求或计费 |
| 整轮预算 | 默认总时长240秒、模型4次、工具尝试8次、已报告Token120000、单次输入48000 UTF-16字符；超额为 budget_exhausted，不发布迟到新答 | 时间/调用/字符限制是硬边界；Token在供应商报告后结算并阻止后续步骤，不能保证计费绝不跨过阈值；未知用量不按零计 |
| 分类恢复 | 参数冲突、参数错误、鉴权、权限、空结果、限流、超时、网络、取消、预算、保存及未知错误分别保留类别和恢复建议 | 仅只读工具网络/限流/超时最多自动重试一次；模型失败不自动重复收费，用户可手动恢复。参数与权限错误不自动重试 |
| 上下文 | 保存原始目标、明确关注、范围、早期/近期原话、待查条件和失败信息；有界摘要和裁剪位置进入各阶段 | 不是模型推断全部用户约束，也不是长期记忆；预算不够有遗漏标识，原消息仍可通过任务JSON定位；Token仅粗估 |
| 失败Trace | 成功/失败/超时/取消均有模型runId、任务、版本、阶段、时延与终因；工具有callId、attempt、供应商requestId及服务版本 | 未报告usage为null；没有精确费用估算；不保存隐藏思考。Trace写盘失败有warnings，不能承诺磁盘故障时仍有完整磁盘记录 |
| 保存失败 | 首次关键保存成功才开始研究；后台Promise统一捕获；显式未保存警告和“重试保存”；完成但仍saving时继续轮询 | 单进程文件持久化；重试保存不重跑模型。重启只恢复已保存记录，运行中任务标明中断，不自动后台续跑 |
| 效果评测 | 8个案例；本地结构检查；逐项金融语义、异常行为、用户理解记录 | 金融正确及用户理解仍需人工证据，未评项为pending；没有据此宣称真实用户效果已通过 |

补查增加逐工具检查点：第一表成功、第二表失败后，可从同范围成功证据继续。检查点与逻辑操作 `operationKey` 绑定，恢复当前操作不能用同公司旧年份检查点覆盖新的期间。旧答案始终保留自己的 evidence 与 researchScope。

运行执行成功和研究结果分开：`status=complete` 表示本轮答案生成；`researchOutcome` 区分 answered、partial_answer、waiting_external_evidence。当前尚未实现逐题必答条件驱动的自动研究成功判定。

## 界面与接口

- 运行中：阶段、已等待时间、总时限和“停止”。
- 停止后：保留结果与资料，可“恢复本次操作”；恢复产生新 revision 和新预算，不重复确认用户看法。
- 失败后：解释错误原因和适用恢复方式；成功取证检查点可单独打开，不混入旧分析的来源。
- 保存失败：独立警告与重试保存；不能将内存中的内容误认为已经落盘。
- “本轮运行记录”按需展开；完整JSON：`GET /api/tasks/:id/trace`。包含各轮执行、模型与工具事件、预算、检查点摘要与错误。不包含密钥或隐藏思考；资料仍可能有用户原文，不应直接公开分享。
- `POST /retry` 校验 expectedRevision 和 operationId；`POST /persist` 只重试保存。

预算通过启动进程环境变量设置，见 `.env.example`；改 `.env.local` 的扶摇Key不改变预算。每次新操作/手动恢复都建立新的整轮预算，尚无跨会话的账户级费用限额。

新增Trace字段从这次更新后的调用开始完整记录；旧任务可以读取，但过去没有采集的失败和用量不会补造。

## 如何复验

```sh
npm test
npm run verify:runtime
npm run build
node scripts/evaluate-research.mjs --task artifacts/acceptance-review/followup-result.json --case business-understanding --output artifacts/runtime-verification/evaluation-example.json
```

`verify:runtime` 创建隔离本机服务，拦截模型及MCP返回，使用“合成验收虚构公司”，不调用真实外部服务。它验证HTTP、持久化和协调机制，不验证金融事实。测试服务结束后会退出；合成任务明确标记 isEvaluation，不应作为主演示的真实公司材料。
