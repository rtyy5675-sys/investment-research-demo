# 用户与面试官复验 · 2026-10-15

## 结论

当前版本具备局部的信息解释和判断辅助能力，可作为本机运行的研究辅助原型验收；尚未证明目标用户能够因此更准确地理解信息、形成自己的判断。

“允许用户保存原话、AI 不替用户改立场”是必要的归属机制；它不能代替解释、比较和核对，也不是独立判断已经发生的证据。

本轮只做验收，未修改产品代码。没有真实用户访谈或理解测试，也没有将模型输出当成独立核实的金融事实。

## 本轮实际任务

- 任务：`324a3e1e-7426-497f-a196-5f162bd66006`，模型使用 `research-decision-v3.2`。
- 初始输入：询问比亚迪 2025 年收入、利润、经营现金流如何合看，并明确“不懂财务，先用日常语言讲最重要的一件事，再说明下一步只需核查哪项”。这是验收输入，不是用户访谈记录。
- 首轮实际取得扶摇 MCP 利润表和现金流量表。回答指出三项指标方向分化、收入增长不足以支持经营整体改善，以及现金流净额下降不能直接归因为回款变差。
- 界面未展示生成结果的 `summary`，直接展示分析段落及大量金额。`src/ResearchDecision.jsx:25` 仅在没有 `analyses` 时渲染摘要。
- 继续输入：“我不知道去哪找这些补充资料，也不想自己读整份年报，你能直接帮我查清这个条件吗？”
- 第二轮实际新增资产负债表，解释时点应收余额不能替代现金流补充资料；仍未取得关键资料，`nextAction` 为 `external`，要求提供年报 PDF 或链接。
- 当前目录没有年报检索、PDF 提取或网页查询工具，页面也没有完成这类资料接入的主链路。不能把“请提供链接”视为已实现后续核查。

原始记录位于 Git 忽略的 `artifacts/acceptance-review/initial-result.json`、`followup-result.json`；截图为同目录 `followup-screen.png`。本轮没有为截图修改结果。

## 从用户角度

### 已经提供的帮助

1. 能纠正常见但影响研究方向的跳跃：收入不等于销量，收入增长不等于利润同步改善，现金流净额不等于客户回款质量。
2. 能让用户修改本轮关注，保留适用证据，避免重新描述全部上下文。
3. 将 AI 分析和用户看法分开保存，允许不表达立场就结束研究；这是可保留的交互选择。

### 已观察到的不足

1. **首要结论被隐藏。**用户明确要求先讲最重要的一件事，模型生成了对应摘要，界面却未展示。问题同时涉及呈现和任务遵循，不能仅靠再加 Prompt 解决。
2. **证据标签的对象不直观。**“与该主张相反”“支持该主张”旁边显示的是问句，真正的 `claim` 只放在 `title` 中。窄屏用户难以看见究竟评价哪个陈述；标签也不能被理解为独立专家已经核验。
3. **关键补查停在专业资料名称。**“营运资金变动”说明了查什么，却没有帮助不懂财务的人完成查找、解释和更新判断。
4. **已有证据没有解释充分。**既有原测试公司主任务问利润来源和持续性，回答只说“收入减营业成本的差额扩大”。按保存的 MCP 原始字段，差额可由约 769.35 亿元算至 884.94 亿元，增加约 115.59 亿元；营业利润增加约 103.33 亿元。可以先展示有限的会计勾稽及剩余待解释差额，再追查业务原因。上述计算用于检查回答是否充分利用给定证据，未经公司原始公告交叉核实，不能据此声称识别了业务因果或全部利润贡献。

## 从面试官角度

有实际交付证据的能力：真实 MCP 查询、问题范围与证据隔离、关注变化后的证据复用、用户看法归属、部分失败和版本处理。历史有限对照没有证明多角色优势，保留这一结果比夸大角色数量更可信。

尚未证明的能力：真实需求强度、用户理解的提升、研究任务的实际完成、对同工具分步单助手的增量价值。既有 22 项检查主要证明状态、结构和部分计算处理，不等于这些价值已经通过验收。

另外，核验阶段在最终回答生成之前，后续校验主要约束结构、范围、引用 ID 和有限数值表达。它没有完整证明最终每条主张都得到引用支持。后续应对核心结论做最终核验，并展示能够定位到的字段或原文，不用“有引用”替代“引用支持结论”。

## 优先修改和验收条件

| 顺序 | 具体修改 | 通过条件 |
| --- | --- | --- |
| P0-1 | 先解释现有证据：一句日常语言摘要、一条可复算的变化关系、明确的未知项。显示证据标签对应的具体主张。 | 无需打开 Bot 工作记录，读者能说清发生了什么、哪些解释已有支持、哪个解释仍缺证；显示值可追溯复算。 |
| P0-2 | 为主演示接通一次关键原始资料补查，可先支持带出处的粘贴材料，或一个真实披露查询入口。 | 同一任务完成初步判断→关键缺口→取得资料→更新解释；明确新证据增强、削弱或未改变原判断的哪一部分。 |
| P1-1 | 对最终核心结论做数值、证据支持和推断边界核对，引用定位到字段或段落。 | 能发现并暴露一条错误或过度推断；资料不足时保留可回答部分，不把未分析写成无法分析。 |
| P1-2 | 进行小规模真实理解观察，并做一组同资料、同工具的普通助手对照。 | 保存原问题和操作；用户用自己的话解释关键依据、区分已知与未知、说出会改变判断的一项新证据。记录误解和失败，不只记满意度或保存观点次数。 |

可先邀请 3 位目标用户，用于发现具体理解障碍，不用于宣称总体可靠性或普遍优越。理解核查属于试用观察，不要求产品每轮逼用户答题或表达立场。

“我的看法”可后续增加用户主动请求的整理辅助，例如归纳其已表达的依据与保留条件，再由用户修改确认；它的优先级低于上述解释和补查闭环，不能由 AI 自动代写或确认立场。

## 正式提交边界

原题还要求评审可访问、可操作的 Web URL、源码仓库和 README。本机入口只能证明本机运行；当前不应宣称正式交付已经完成。对外材料需另选可分享的验证记录，剔除密钥、登录凭据和受限数据。

建议下一步集中交付：**充分解释已有证据，接通一次关键补查，并让真实用户证明自己理解了判断依据。**新增 Bot、栏目或更长的约束不是当前首要工作。
