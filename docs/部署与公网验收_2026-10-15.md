## 失败与修复

1. 首次 Render 构建失败，日志为 `vite: not found`。原因是 `NODE_ENV=production` 时默认安装跳过开发依赖。构建命令改为 `npm ci --include=dev && npm run build`，本机生产环境构建、远程 CI 和 Render 后续构建均成功。
2. 首次两次公网研究均在 MCP 工具发现阶段遇到 `fetch failed`，没有发布编造结论。模型规划调用成功，但当时没有取得有效财务证据。
3. 对 MCP 握手和工具发现增加一次有限重试，补充脱敏后的底层网络错误码；初始化重试会创建新 Client/Transport。取消、权限错误不重试。新增 5 项恢复测试通过，总计 158 项单元测试通过。
4. 重新部署后的一次真实任务完成。本次成功任务没有发生工具失败，因此不能据此宣称已证明重试消除了上游网络故障；真实瞬时超时仍可能发生。

## 使用与维护边界

- Render 免费实例可能休眠，首次打开可能等待较久；重启、休眠和重新部署后的研究状态不保证保留。
- 使用公开 Git URL 部署，未授予 Render GitHub App 仓库权限；更新代码后使用 `Manual Deploy → Deploy latest commit`。Blueprint 配置变更需要手动同步并审查。
- Web 密码、模型 Key、扶摇 Key、原始 Trace 与本地用户状态不进入公开仓库；访问凭证单独提供给评审。
- 本次只证明公开源码可访问、Web 已部署，以及一条真实财报研究链路完成。已有产品验收中的失败和范围限制仍见[系统性测试报告](系统性测试报告_2026-10-15.md)，不能改写成“全部验收通过”。
