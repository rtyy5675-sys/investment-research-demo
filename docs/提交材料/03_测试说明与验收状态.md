**验收结论：当前158/158项单元测试通过；一条公网主链路完成；完整产品场景尚未全部通过。** 未通过项见第三节，不能用工程回归替代场景验收。

## 三、使用边界与后续验证

- **金融补查稳定性：**本轮美的首答出现归母/整体净利润口径混用，被核验拒绝；补查中又出现不受支持的推算和把沿用资料称为新增，更新未能稳定发布。资料取得成功与任务完成分开记录。
- **统一金融输出拦截：**合成复现中，结构校验函数接受含明显买卖建议、收益保证的结果；完整链还有模型核验，但不能宣称程序已兜住所有可见文本。澄清路径也需统一覆盖。
- **受限数据：**没有提交原始 MCP 数据包或完整付费资料，但公开截图含财务数值与查询结果，公开展示/再发布授权尚未核实，不能标为授权已确认。
- **尚未验证：**真实多账号端到端隔离、广泛 PDF 格式/扫描件、真实手机设备全覆盖、完整多轮攻击集、云端跨重启持久化、用户理解提升与长期留存、同配置 Claude 对照。

事实、推断与不确定信息的表达项按本轮用户验收口径列为正常，原始措辞观察保留作非阻塞的表达改进参考；这项处置不改写其他失败与待确认状态。

## 四、主链路的具体验收标准

| 检查点 | 通过标准 |
| --- | --- |
| 问题与归属 | “想知道是否”不转写为用户断言；他人观点不归给用户 |
| 取证与引用 | 公司、报告期、币种/单位、合并口径正确；每项引用能回到实际取得资料 |
| 研究推进 | 新证据解释旧问题，已解决事项不反复打开；没解决就明确阻塞 |
| 失败恢复 | 不用缺失当零，不伪装取数成功；旧版本迟到不能覆盖新任务 |
| 记忆控制 | 当前指令优先；停用后不自动读写；纠正能影响后续会话 |
| 用户理解 | 用户能说明本轮已知、仍未知，以及下一步为什么值得查；目前尚无真实用户观察结果 |

## 五、复现方式

在源码目录执行 `npm ci`、`npm test`、`npm run build`。工程专项脚本与测试夹具在 `scripts/`、`tests/`；真实模型/MCP 复现需自行配置服务凭证，会产生供应商调用和新的验收任务。
