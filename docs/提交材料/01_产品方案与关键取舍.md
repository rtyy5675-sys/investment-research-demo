# 产品方案与关键取舍

## 一、目的与已确定的方向

我希望见微成为个人投资研究 Agent：持续理解用户正在研究什么、为什么关注、哪些疑问尚未解决，以及用户明确表达的担忧、期待与取舍。每次有新信息时，Agent 能接着这段研究继续，而不只是重写一份通用报告。

这是已经确定的产品方向。本次练习以 24 小时为范围约束，只交付核心研究记忆与财报研究的最小闭环；其余个人 Agent 能力是后续迭代。方向确定不等于市场效果已验证。

## 二、目标用户与触发场景

目标用户是会反复关注同一家 A 股公司、阅读财报或财经观点的个人投资者。具体触发是：看到新披露后，不清楚它对自己之前关心的问题意味着什么，又不想重新翻旧报告、复述背景或核对口径。

一个可操作任务是：“我上次想弄清经营现金变化来自哪里。这次资料是否补上了那个缺口？哪些认识应更新，哪些仍不能确定？”公司和关注点由用户当前输入确定，不固定绑定演示公司。

这类需求来自候选人在需求讨论中表达的真实疑惑。当前没有目标用户访谈样本、连续使用观察或付费证据，因此将“减少重复交代与重复研究”作为价值假设，没有将其包装成已验证需求。

## 三、从用户的人性出发

用户可能同时想理解信息、寻找机会、确认原有看法，或缓解决策的不安。产品先帮助他把已知资料读明白，不要求先填投资画像、承认知识不足或选择看多看空。确实影响公司、报告期或结论的歧义才澄清。

“懂用户”通过可纠正的关注和研究进度体现。用户问“是否成立”，系统保留为疑问；转述他人观点不记成用户立场。对恐惧、贪婪和风险偏好的理解应来自用户明确表达，不从单次问题推断人格或持仓，也不因用户偏好而改变证据强弱。

## 四、核心工作流

1. **确认当前任务：**识别一家公司、年度或累计报告期和用户想弄清的问题。
2. **恢复适用背景：**读取同一用户、同一对象的研究关注、已解决事项、未决条件及证据定位；当前明确要求优先。
3. **取证和解释：**扶摇 MCP 查询已接入财务字段，比较同口径期间；程序计算金额与同比，模型解释与当前问题的关系。
4. **有针对性补查：**已有能力可覆盖缺口时检索公告或上传文本 PDF；核对公司、期间、合并口径、单位和引文。
5. **更新判断和进度：**说明新证据解决了什么、还有什么未解决；有效结果发布后更新研究记录。
6. **允许纠正与退出：**修改问题或关注、本次不用、停用、删除；失败保留有效结果，旧版本不覆盖新任务。

## 五、AI 相对搜索、规则和普通对话的增量

| 原有方式擅长什么 | 此处交给 AI 的工作 | 程序保留的责任 |
| --- | --- | --- |
| 搜索找到财报与公告 | 把自然语言疑问转成有公司、期间与资料范围的研究任务 | 标的消歧、工具白名单与权限 |
| 数据产品提供字段 | 解释字段变化对用户当前问题的意义，选择值得补查的缺口 | 同比与差额计算、单位与范围校验 |
| 人工阅读原文 | 在文本型财报中提取所需字段并给出可核对引文 | 引文存在、表格勾稽和来源定位 |
| 普通聊天保存历史 | 恢复相关关切与进度，让取证和回答接着旧问题推进 | ResearchCase 记录、版本、失效与用户控制 |

使用分步流程并不自动证明 AI 增量。现有有限对照未证明多角色优于同工具、同预算的单 Agent；也尚未完成真实的有无记忆公平对照。后续应比较任务完成、重复交代、关键误解与复核成本。

## 六、实现结构与界面取舍

主界面保留一个研究助手对话框。研究、核验职责的工作消息在侧栏呈现，用户可将问题带回主对话；无需阅读全部协作记录才能理解结果。默认由同一助手分步完成规划、解释、最终核验，不把 Bot 数量当作产品价值。

后端负责模型适配、MCP 调用、公告/PDF、证据、状态与版本控制。ResearchCase 是连续研究的领域记录，包含关注、已解决与未决问题、证据引用及当前结果。用户原话、AI 暂定理解、研究状态与用户确认的看法分别处理。

修改分为本轮关注、长期默认与观点归属纠正；停用记忆后不自动读取或写入。模型不能仅因为上次分析说过，就把它当作当期财务证据。运行记录可展开查看调用标识、输入范围、取证来源、结束原因与保存状态。

## 七、首版范围与明确未做

已接入单家 A 股年度及一季度、上半年、前三季度累计财报；扶摇财务查询；沪深公告检索、文本 PDF 与受支持的现金流字段补查；研究记忆控制；财务图表、数据表和证据入口。

未完整支持多公司、港美股、市场共识和信息计价、扫描 PDF OCR、任意附注提取、历史时点数据库、持续监控、真实多账户隔离及云端长期存储。无可识别 A 股标的的独立表格/材料研究不纳入本次交付范围。

产品不提供确定性涨跌预测、收益承诺或直接买卖决定。现有拒绝样本有效，但统一的确定性输出拦截仍不完整，不能宣称任意诱导均可防住。

## 八、后续版本与价值验证

| 阶段 | 迭代方向 | 验证什么 |
| --- | --- | --- |
| 研究连续性 | 独立用户身份、可靠存储、纠正与删除在后续会话生效 | 少重复交代，不重新打开已解决问题，不错配用户或公司 |
| 更懂个人 | 维护明确表达的疑惑、关注、担忧、期待及判断条件 | 记忆确实改变取证与解释，而不是只增加熟悉感 |
| 关注驱动跟踪 | 用户选择对象与条件，出现新披露后解释其关联 | 提醒相关、可追溯、可关闭，不以频繁通知代替价值 |
| 扩展研究背景 | 行业、多对象、估值、市场预期及价格反应 | 数据有时间戳和比较基准，结论不越过证据 |

下一步邀请 3–5 名目标用户，观察其最近一次研究及后续复访；用同模型、同工具与同资料比较有无记忆。记录任务完成、重复交代次数、已解决问题重复率、误归属次数、复核时间，以及用户能否说清“依据变了什么、还缺什么”。小样本用于试错，不用于宣称长期留存或收益。
