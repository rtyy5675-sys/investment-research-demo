## 三条复验路径

1. 主链路：新公司年度研究 → 初步解释 → 原始财报补查 → 核对判断变化。自行配置模型和数据Key后运行。
2. 缺失/失败：错误公司PDF、无文本PDF或上游失败 → 明确阻塞 → 保留上版结果；上传成功不是提取成功。
3. 极端/归属：负现金流、零或负基数、累计季度、用户问是否 → 不补零、不输出不适用同比、不改写立场。程序规则有测试，完整真实合规诱导仍待验收。

## 命令

```sh
npm ci
npm test
npm run build
npm run verify:runtime
npm run verify:memory
```

后两项隔离本机服务、使用合成夹具，不需真实Key。真实补查执行 `node scripts/verify-disclosures.mjs`，需要运行中的本机服务与可用配置，会产生真实模型调用并创建任务。

8个效果案例与9条连续记忆序列在 `evaluation/`，是判据与计划；未运行项保持pending。自动结构pass不能替代金融语义核对或真实用户观察。
